SUPABASE CONFIGURATION FIX
================================================================================

Problem Encountered:
- Initial startup threw "Invalid Refresh Token: Refresh Token Not Found" error
- Browser console error: AuthApiError

Root Cause:
- Supabase client was configured with autoRefreshToken: true (default)
- Attempting to refresh non-existent session on page load
- No user session established yet

Solution Implemented:
- Updated lib/supabase.ts to disable autoRefreshToken
- Set persistSession: true for proper state management
- Disabled URL-based session detection
- Graceful handling of auth checks without active session

Status: ✅ RESOLVED - App boots without auth errors

================================================================================
TELEMETRY ERROR FIX
================================================================================

Problem Encountered:
- Server-side errors: "Invalid URL: /api/telemetry"
- TypeError: Failed to parse URL from /api/telemetry
- Telemetry service attempting fetch() with relative URL on Node.js backend
- Errors flooded console every 5 seconds (flush interval)

Root Cause:
- HttpTelemetryPublisher trying to use fetch() on Node.js context
- Relative URLs only work in browser (have window.location context)
- Server-side has no window object, so relative URLs are invalid

Solution Implemented:
- Added typeof window === 'undefined' check in HttpTelemetryPublisher.publish()
- Skip publishing on server-side (Node.js context)
- Only publish from browser (client-side)
- Construct absolute URLs when needed: `${protocol}//${host}${url}`

Status: ✅ RESOLVED - No more telemetry console errors

Symptom: Browser console shows "Invalid Refresh Token: Refresh Token Not Found"
When: On page load, before any user interaction
Why: Supabase trying to auto-refresh non-existent session

Fix Applied:
- Location: lib/supabase.ts, line 8-12

- Set persistSession: true (save session to localStorage)
- Set detectSessionInUrl: false (don't parse URL for session)
